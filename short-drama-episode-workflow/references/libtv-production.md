# LibTV 画布制作

主控技能负责创作、剪辑和审核。LibTV 插件负责画布、资产、模型和任务。每次使用工具时按当前插件 schema 填参数。用户只要求查看或报价时，沿用本轮只读范围，使用现有画布、节点或报价界面。

## 定位项目与剧本

1. 用 `doctor` 核对连接、账号和本次执行许可。按用户指定或交接记录定位项目，用 `target_project` 核对本集画布 ID 和所属空间。剧本源画布与本集投产画布可以不同，分别记录。续作优先查找用户建好的本集画布，有同名项时按空间和已有交接辨别。
2. 用户以 LibTV 定稿为准时，从授权的剧本节点读取实际章节。通过 `list_screenplays` 或画布节点定位，再用 `read_project_file` 或对应剧本工具读取完整内容，按分页字段取齐。将实际版本、来源、哈希写入本地制作依据。已有可靠原片时，先按任务和节点清点，接到收片或剪辑。
3. 生成前用 `search_models` 查当前账号可用的模型，再用 `get_model` 读取实际输入契约。按本集要求选模式、输出规格、时长和数量。预算按当前报价计算，尤其比较视频延长是否把参考视频时长计入费用。

## 复用与绑定

- 既有 LibTV 资产用 `get_asset` 核对身份和版本，用 `apply_asset_to_canvas` 加入本集画布。跨集同场需要续接时，从上一集采用版或上一镜原片提取真实末帧或最后叙事帧。跳时、换衣或换地点时，改用适用的身份和场景参考。
- 本地抽帧或其它已获授权的本地素材，按 `upload_ticket` 返回的分片信息上传实际字节，再调用 `upload_complete` 和 `upload_media`。使用已入画布的确切节点 ID 做绑定。平台审核待定时，沿用同一上传凭据、参数和幂等键恢复挂载。
- 在模型支持时，精确开场用 `startFrameNode`，有确切的结束状态才用双帧模式。多图、声音或视频参考走对应的参考模式。首尾帧槽和多参考槽按工具契约选其一。正文用平台原生节点引用，并写清每份素材控制的人物、构图、空间或声线。绑定后用 `read_node` 回读实际槽位和顺序。
- 新图及后续投产用抽帧按项目约定归入本地和 LibTV 资产库。用 `save_asset_from_node` 保存已通过资源审核的节点，再用 `get_asset` 核对。索引记录来源文件和帧号、版本、哈希、节点和资产 ID、用途及采用状态。

## 报价、提交和恢复

1. 按主控要求先保存投产快照，逐镜列出参考、完整提示词和参数。视频使用当前 `generate_video` 的准备模式，例如 `run:false`。写入待执行节点时回读模型、提示词、绑定、画幅、分辨率、时长、声音开关和数量。生图或语音按当前工具支持的准备和报价方式执行。模型和参数查询走只读能力。
2. 核对报价与同一节点的参数。插件未返回当前价格时，在已登录的 LibTV 浏览器打开目标画布，选中同一节点核对实时积分和账号余额。留存报价依据、时间、逐项金额和合计。按主控技能核对本集授权。创作者已允许按实时报价直接生成时，告知并记录价格后提交。返修采用新版本和实时报价，继续核对授权范围。
3. 提交已核对的待执行视频节点时使用当前插件的执行入口，例如 `update_node` 的 `run:true`。每项生成用独立稳定的幂等键，保存实际生成任务 ID、节点、参数版本、报价和回执。`cop_` 画布操作回执只说明画布写入。已受理的生成用 `task_status` 查询实际任务。结果未知时先查状态和扣费，再按工具要求使用同一幂等键恢复原请求。仅在确定需要新一版时为其新建任务。

## 收片、后期和回传

- 待任务完成且资源可下载，用 `prepare_project_delivery` 指定当前画布及实际输出节点，按用户选择和账号权限取得原件。记录 Resource ID、版本、字节和 SHA256。下载后探测规格并完整解码。画布卡片、任务成功和本地原件收片分别记状态。
- 后期沿用主控的剪辑、配乐、字幕和实片复核。对白按项目的声线偏好选同镜原声或匹配的配音，字幕按定稿逐字核对。查清缺陷是生成原片、接镜、混音还是输出造成，再决定局部修复或补镜。
- 按用户要求把经过本地复核的验收版或正式采用版上传到本集画布。挂载若待资源审核，用相同请求恢复，保存新节点和 Resource ID。可取回原件时对照本地文件哈希。画布命名与本地版本一致，历史版本保留可追溯。资源审核与创作验收分别记录。
- 按真实报价和账户流水对账，区分已报价、实际扣费和未知结果。交接写明本集画布、采用的素材与成片、审核状态、费用和可供后续复用的资产。
