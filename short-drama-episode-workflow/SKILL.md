# 短剧单集完整制作

从用户指定的项目、集号和阶段开始。用户要正式成片时，以本集成片审核通过为交付条件。只要报价、素材、预览或修一处时，按指定范围执行。整理流程或创建技能时，留在本地资料范围内。

## 逐节点核对制作流程

开工时按本轮范围把下表的节点记入本集现有制作记录或交接。标明「待做」「待复核」「通过」或「不适用」。通过时写明版本、产物或回执及实际核对结果。不适用时记录剧本、创作者决定或任务范围依据。从中途接手时，按当前采用版本查验已有产物，沿用核验通过的节点。

| 节点 | 推进依据 |
|---|---|
| 制作依据与渠道 | 本集定稿、创作者决定、规格、渠道和目标画布或工程已核对 |
| 资产、分镜与提示词 | 按范围核对现有资产或补齐所需素材，确认分镜和实际投产内容能落实剧本 |
| 投产与收片 | 新生成前完成适用的参数、报价和授权核对，收片时核实原件与任务回执 |
| 定剪与声音方案 | 核对实际入出点和对白边界，记录是否用配乐及各场景、镜头的声音安排 |
| 配乐、混音与字幕 | 逐项核对适用的选曲与授权、混音、字幕时间和最终默认音轨 |
| 成片复核与返修 | 按最终版本检查技术、剧情、表演、声音、字幕和接镜，修复发现的问题并复核 |
| 正式交付与同步 | 核对交付副本、附属文件和哈希，按约定同步并回读，更新交接 |

进入下游前核对它依赖的节点，发现遗漏就回到对应步骤补齐。素材、剪点、提示词或采用版本变动时，把受影响的下游节点重新列为待复核。正式交付前逐项关账，所有本轮适用的节点都须有通过证据。

## 换机与自动安装

在新电脑首次执行制作、或发现依赖技能缺失时，从本技能所在目录运行安装器的 `--check`。返回 0 就继续，返回 2 就用同一入口去掉 `--check` 自动补装并重新检查。其他错误按输出修复。只查询技能、报价或只读审查时，保持只读。

- Windows 使用 `Install-Windows.cmd --check`。由 Codex 执行补装时直接运行 `scripts/bin/windows-amd64.exe` 或 ARM64 对应版本以免等待按键。默认实体目录为 `D:\Codex\skills`。
- macOS、Linux 或 WSL 使用 `sh ./install.sh --check`。支持 Intel/AMD 64 位与 ARM64。
- 使用包里锁定的依赖版本，包含泡漫定制的 Seedance 技能。已存在不同内容的同名技能时，保留用户文件并列出冲突。安装后如果当前会话的技能列表尚未刷新，可从已安装目录读取本次所需的 `SKILL.md` 继续执行。

整包迁移、路径选择与运行环境说明见[换机安装](references/portable-install.md)。

## 通用默认规格

| 项目 | 默认值 | 使用阶段 |
|---|---|---|
| 画幅 | 16:9 横屏 | 新生成的图片、分镜构图、视频生成与最终交付 |
| 视频分辨率 | 480p | 视频生成与成片导出。横屏常用 854×480，验收时同时核对显示比例 |
| 单集成片时长 | 最多 90 秒，含片头、片尾、转场和黑场 | 分镜预留时间，定剪控制总长，交付前读取最终文件的实际容器时长。各镜原片可留剪辑余量 |

每项独立取值，依次采用本轮明确要求、当前项目对本集生效的要求、通用默认值。只指定竖屏就改画幅，视频仍用 480p、成片仍至多 90 秒。项目另定时长上限就使用该值，明确不限时长就取消上限。创作目标与硬上限分开记，例如项目要求约两分钟时按两分钟安排，不用默认 90 秒拒收，也不把“约两分钟”当成精确上限。

## 确定本次制作依据

1. 以本轮指定的目录或明确选中的项目为根。读取其中已有的项目指令、创作者决定、本集原稿、采用记录与素材。使用 short-drama 目录约定的项目可从 `short-drama.json` 和本集交接进入。只有一份新剧本也可开工，先做剧本与分镜准备。多个目录都可能是目标时，先确认归属。
2. 把本集最终采用的画幅、分辨率、时长要求及各项来源记入交接，再确定提示词语言、生成渠道、声音和字幕。新建项目时将生效规格带入初始化和下游制作工具。项目未填、模板预填且未经采用的项，均沿用技能默认值。
3. 首集或独立单集从剧本建立人物、场景和声音基准。连续剧集读取本剧上一集采用版及结尾状态。已有合格原片从收片核验接手，已有底片从剪辑工程接手。缺原稿时核实是否已委托创作。地点、身份和规则只在所属项目的交接中维护。
4. 根据本集实际需要为关键动作、台词、反应和片头片尾分配帧数，原片留剪辑余量。接近时长上限时先收紧空等和重复反应，保留转折和完整尾字。新窗口核对已提交任务、已采用版本和未关闭问题。只读准备时不执行会写入项目的 init、prepare 或 confirm。

## 按剧本落实表演

- 以本集采用的《剧本.md》和创作者已确认的改动为准。逐场读对白括注和动作描写，把写明的神态、语气、动作幅度、速度、先后和停顿传到对应镜头。写实风格、人物常态、题材和模型建议用于补足剧本留白。创作者想对照另一种演法时，在受影响镜头标明试拍变化和采用状态。
- 分镜在现有的「唯一动作」「终点」「声音」里写清关键表演及其触发。视频提示词对照同一处剧本，把表演落实到当前景别可见的动作、可听的发声和相对时序。比如剧本写「迫不及待举碗、水瞬间飞走、人僵住」，就给举碗、突发和骤停各留清楚的一拍。镜长紧张时先调切点、镜长或拆镜，保住剧本规定的力度和转折。
- 投产前核对平台实际保存的提示词和时序是否保留这些表演。接手已有素材时从对应剧本段落查实片。在剧情转折或片尾悬念处，结合实片核对反应是否看得清、语气变化是否听得到、快慢和停顿是否落在原稿要求的位置。

## 选择制作渠道

- 优先采用用户本轮指定的渠道。续作且用户未另选时，沿用本项目已有的制作渠道，并定位**本集**画布或片段。本集原片已齐时从核验和后期接手。
- 用户指定 LibTV，或项目已在 LibTV 制作时，走 [LibTV 画布制作](references/libtv-production.md)。该路线通过 Codex 的 LibTV 插件核对剧本、画布和原片，并将本地成片同步回本集画布。
- 用户选泡漫，或选用 Seedance 且项目与本轮都未指定渠道时，读 [泡漫浏览器投产](references/popreels-browser.md) 和 `byted-ind-ecom-prompt-to-video`。使用其他已选渠道时，按相应工具的预检、提交、收片流程执行。
- 已选渠道暂时不可用时，说明具体缺口，继续本地准备或剪辑。切换付费渠道按当前委托和授权判断。

## 从原稿到可拍摄的镜头

| 正式文档 | 负责技能 | 进入下一步的依据 |
|---|---|---|
| 剧本.md | `short-drama-write` | 原稿单独存档；会改变因果、姓名或规则的歧义取得作者决定并留痕 |
| 视觉设定.md | `short-drama-assets` | 锁定身份、服装、地点、道具及其进出状态。分清镜头展示的事实和角色的推测 |
| 图片提示词.md | `short-drama-image-prompts` | 逐项匹配真人物、地点、道具或既有参考图，标明缺少的变体 |
| 分镜.md | `short-drama-storyboard` | 每镜写明要让观众知道什么、起止状态、动作执行者、对白、视线和相邻镜头 |
| 视频提示词.md | `short-drama-video-prompts` | 按实图、镜长、表演及收音方式写动作和发声窗口，区分画内对白、画外音及静默 |

这些文档通常在 `剧集/EPxxx/`。如需生图，读取用户所选渠道对应的技能（GPT 生图用 `imagegen`），保存真实参考图和新图。先看图，核对构图方向、人物和状态再绑定。所有新图按目标画幅构图，变体另存。逐镜 TXT、平台导入文本等从正式文档导出，改稿后同步，并运行 `short-drama` 的跨文档检查，核实引用的媒体确实存在。

需接同一场戏时，从本剧上一集采用版取[真实尾帧或最后叙事帧](references/media-validation.md#跨集取帧)。按需要取人物、空间反打和干净原声。换画幅时等比保留主体，调整构图。将上集末镜、本集首图、生成首镜并排比较，再做依赖该镜的段落。明确跳时则只承接仍相关的人物、道具与声线。

## 多视角参考图

新做可复用参考资产时，在 `图片提示词.md` 写明各个视角及其用途。多视角板的整张画布和独立输出的参考图默认用 16:9 横屏，按本集生效画幅调整。优先复用已有图和合格原片帧，只补本次缺少的视角。创作者指定的版式优先。

- **角色定妆**默认一张设定板内展示同一人的正面、侧面和背面全身，统一比例、光线、服装、发型和配饰。常用斜侧机位或面部特写可补三分之四视角或头肩近景。并排核对五官、体态、衣着及配饰位置。
- **场景**按分镜建立主机位和实际要用的另一观察方向，例如工位正面与过道反打。标明每个视角的机位和朝向，并排核对门窗、家具、通道、人物站位依据和光源是否对应。
- **道具**仅为确需单独复用的道具补视角。选能交代形制的正面或斜侧面，再展示后续动作、握持或特写所需的另一面或功能细节。各视图保持同一尺寸、材质和开合状态。
- **输出与绑定**优先用一张清楚的多视角板，逐格指定角度。图格太小或模型需要独立参考时，选用清楚的单格或补必要单图，并记录原板、选用角度和版本。视频首帧、尾帧各用一张完整的单视角画面，优先从通过核片的原片抽取；核对人物站位、持物、身体与家具的遮挡关系后再绑。多视角板用于身份、造型、空间或道具参考。

## 对白场景的镜头默认

普通双人对话优先保留同框交流，减少随发言人变化而逐句切换单人近景的刻意感。将这项默认偏好交给分镜、起始图、视频提示词和剪辑共同落实；创作者指定的镜头风格优先，已接受成片只按本次委托范围处理。

- 分镜按完整交流和戏剧节拍划分，一个镜头可以承载多轮对白。单人近景与正反打用于重要信息、决定、情绪转折或听者反应；不设固定镜头比例，也不要求整场一镜到底。
- 同框段先准备能看清双方脸部、站位与视线的起始画面，再写明确的发声顺序、自然停顿和听者反应。需要保持同框时，明确不随说话人变化切换单人景别。
- 生成任务按对白、动作和反应所需的实际时长安排，不为方便核音而默认一句台词生成一段。单次生成仍可能自行切镜，须核对实际构图、说话归属、口型和反应。跨段连续交流按当前模型能力选择真实视频延长或实际尾帧续接；首尾帧只约束边界状态，不能替代镜头设计。
- 剪辑切点跟随剧情、动作与情绪变化，适当保留听者反应和声音连续性。复核时区分计划内切镜、模型自行切镜与片段接缝，再判断全场是否重复同一种切法；有剧情作用的单人镜头可以保留。

## 生成与后期怎样交接

按选定渠道和实际后期需求读取技能。用户指定使用四技能时，给每项分配与本集内容相符的实际工作，并在交接注明输入、采用的输出和位置。

| 工具或技能 | 收到什么 | 交给下一步什么 |
|---|---|---|
| LibTV 插件或所选渠道的投产技能 | 每镜提示词、已核对的参考图、可选的声线或音效 | 生成原片、平台实际输入、回执与费用 |
| `video-use` | 下载原件、正式剧本、相邻镜头 | 按真实发声与动作裁出的剪辑单、素材入出帧、定剪时轴、无字幕底片及声音分轨；收到下两项的实际渲染层后完成合成 |
| `hyperframes` | 分镜要求的画内文字、动态图形或片头图卡，以及该镜实际坐标和帧率 | 可编辑工程及渲染层。检查运动物体的位置、透视和遮挡；原片已正确呈现的效果可直接采用 |
| `remotion-best-practices`（Remotion） | 定剪后实际对白时间、画布、帧率、避让区域 | 可重建的字幕或时间卡工程、透明渲染层及对应字幕文件。底片与叠层按同一帧对齐；字幕最后合成 |

## 生成与收片

- 先按[投产输入快照](references/production-preview.md)记录每镜完整正文、素材与哈希、各自控制对象、拟用参数和输出目录。按已选渠道准备，优先使用符合当前造型和叙事状态的既有资产。有可用视频帧时，从原件抽取并核对后绑定。场次跳时只复用仍相关的身份、环境或道具。
- 回读渠道实际保存的参考绑定、模型、时长、画幅、分辨率、声音、数量等适用设置和**当前报价**。逐项列出费用并合计，注明返修按实际范围另核价。只询价时在此结束。
- 默认报价后等本批同意。用户明确授权本集按实时报价直接使用积分时，在首笔提交前告知报价并记下授权原文，在覆盖范围内直接执行。补镜新开条目、重新核价，核对是否在本集授权内。已有授权未覆盖新增支出时先询问。不同集的历史支出、确认或账号余额不能代替本批授权。
- 每个已授权镜头只提交一次。回执延迟或下载失败，先查平台历史、任务与扣费，再轮询或下载。对账后仍不能确定提交结果时，记录该镜待核实，继续独立的本地工序。
- 保留原件，以集号、镜号、版本、任务记录、文件哈希关联，探测实际视频、音频和容器时长，完整解码后交剪辑。平台导出若与本地草稿不同，保存实际输入副本供追溯。

## 定剪、混音与字幕

先读 `short-drama-edit` 和[实片、字幕与配乐验证](references/media-validation.md)。对原片查看首尾与全段，动作疑点逐帧；当前只能抽帧时，按约半秒间隔覆盖各镜并标明范围。用原声确定发声边界，留起音、末字和呼吸，再把入出帧、声音跨切、字幕和舍弃理由写入本集剪辑单。剪辑单按项目工具 check、render、verify；外部合成另存可重复使用的工程、命令和输入版本。

定剪时先做干净底片。按需跟踪画内文字。需要对白字幕时，从正式剧本取词，按实际发声落到输出时轴，检查源片已经烧入的字。修订剪点后同步更新受影响的字幕和音乐包络。烧录字幕放在最后一层，在目标观看尺寸下检查折行和遮挡。

### 配乐制作与核验

制作或返修整集成片时，在定剪前完成第 1 步。需要配乐的集数按第 2 至 4 步推进。

1. **确定声音方案。** 读本剧的类型、世界观、创作者要求和已有声音决定，确定适合本剧的音色、编配与节奏范围。再按本集剧本逐场看情绪走向、关键转折、对白和动作声。定位改变情绪或叙事重点的具体镜头、动作或台词，在剪辑单或制作记录写明各段的基调、音乐用途和同期声留白。只有同期声的素材也要做这一步。创作者明确要求无配乐或本集有明确的无配乐设计时，记录依据，后续配乐项记为不适用。
2. **按场景和镜头选曲。** 情绪和叙事作用延续时，同一曲段可以跨场或跨镜。遇到基调明显转变，按转折点判断用同曲的另一段、换曲、淡出或留同期声。两场情绪不同而原曲无法承接时，为后场另选合适曲段或曲目。曲目数量由本集剧本和实片决定。先查项目曲库、已有采用记录和分轨，复用符合本剧类型、对应段落基调且授权清楚的曲目。缺少可用曲目时，用 `free-bgm-search` 按对应段落筛选，核对选用片段的编配、速度和动态是否配合当时的剧情与对白。续集可复用主题或音色，曲段与进退随当集变化。核实实际使用版本的官方来源、许可和署名，再保存音频及依据。创作者指定原创或提供自有曲目时，按其要求制作或接收，并记录来源与使用依据。来源或授权待定的曲目可留作候选，选用的正式曲目须完成核对。
3. **按定剪混音。** 记录实际曲目版本、素材入点、成片起止时间、进退、对白避让和关键音效留白。保留可用的对白、氛围、音效与音乐分轨。在关键字前压低音乐、字尾后恢复。剪点变动后重核这些时间。可用 [mix_bgm.py](scripts/mix_bgm.py) 和[计划示例](assets/music-plan.example.json)，先用 `--validate-only` 核对计划，再运行混音并输出新版本。
4. **核对实际成片。** 在最终 MP4 的默认音轨检查应有音乐的段落、换曲或换段的前后接点，以及对白、关键音效、刻意留白和片尾淡出。实测确认音乐已混入，再直接核听每次音乐变化是否落在剧情转折上，音量是否让对白和动作声可辨。核听未完成时在审核记录列出待审段落，先提供候审版。正式交付时附采用曲目的署名和改动说明。

## 成片复核、返修与交付

**本集所有适用的必查项均已通过、已发现的问题全部修复并复核通过、待核项为零时，才能正式交付成片。**

1. 先将最终编码的候选文件放在制作目录，记录版本及 SHA256。对该文件做全片解码，按本集生效规格核对显示比例、分辨率、帧数和实际容器时长。有音轨时核对声道、综合响度、真峰值及声画结尾。对有声 MP4 运行 [check_delivery.py](scripts/check_delivery.py) 做技术检查，通用默认参数为 `--max-seconds 90`。项目另有要求时按[核验说明](references/media-validation.md#交付副本检查)执行。
2. 从头到尾回放该版本，对照剧本及已确认的改动核对剧情、接镜与表演。关键表演按成片时间码核对神态、语气、动作力度和节奏。按本集要求看实际字幕的文字、时间和遮挡，听默认混音中的关键字与末句，核对口型、音效、配乐和对白的关系。在本集审核记录中写明各项结论与依据。不适用的项目注明原因。抽帧、语音识别与波形可辅助定位。无法核实的视听项标为“待审”，记录缺少的检查。
3. 发现任何问题就记下版本、时间码、现象与修法，将该版标为“待修”。在已有授权内继续返修、重新导出，回查问题段和前后接点，再对新版执行上述终审。需补镜时走本集投产与费用步骤。必查项尚未完成的版本留在制作目录，标为“待审”。
4. 达到正式交付条件后，在本集审核记录中写明“审核通过”及对应文件的版本、SHA256。将同一文件复制到交付目录，核对副本哈希一致后提供成片、审核记录及本集要求的字幕和配乐署名。交接记录采用版本、时长、镜头来源、费用以及下一集可承接的状态。创作者反馈单独记录。

调用示例：“用 $short-drama-episode-workflow 制作这个项目的指定集，按项目规格交付复核后的成片。”
